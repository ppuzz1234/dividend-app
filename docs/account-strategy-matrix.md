# 계좌배분 전략 매트릭스 (기초 데이터)

> 기준: `packages/core/src/plan/accountRooms.js` (2026-07-29)
> 용도: 신규 전략 추가·기존 조건 조율 시의 기준 문서. 엔진 수정 시 이 문서를 함께 갱신할 것.

시스템은 2계층으로 동작한다:

1. **사용자 선택 전략** — 전략 코드(`taxPref`-`isaRollover`, 예: `growth-isa1`)로 직렬화되어
   로컬 스냅샷과 `plan_revisions.note`(`strategy:` / `caps:` 토큰)에 저장된다.
2. **엔진 자동 조정** — 어떤 전략을 골랐든 고객 상황(나이·소득·기납·유동성)이
   순위(`scorePriority`)와 금액(`deriveAutoLimits`, waterfall 클램프)을 덮어쓴다.

## A. 사용자 선택 전략

| 전략 코드 | 최적 고객 조건 | 상세 플랜 (납입 순서·금액 규칙) | 강점 |
|---|---|---|---|
| `growth-isa1` (CUBE 추천 · 기본) | 55세까지 10년+ 남은 30~40대, 총급여 1,500만 초과(공제 실효), 월 여력 50만+, 3년 내 목돈 계획 없음 | ① 연금저축 공제분 연 600만 → ② ISA 연 2,000만 → ③ IRP 공제분 연 300만 → ④ 연금저축 비공제 추가납입(잔여 1,800만 × 나이별 허용률) → ⑤ 일반 잔여. ISA 만기 시 연금저축 이전(+이전액 10%, 최대 300만 추가공제) | 장기 복리 극대화(IRP 안전자산 30% 드래그 회피) + 3년마다 이전 추가공제 + 공제 600만 확보 |
| `growth-isa2` | 만기 목돈을 55세 전에 쓸 계획(주택·교육 등 중기 목적)이 있는 고객 | 매달 배분은 isa1과 완전 동일. 만기 목돈은 ISA 재가입으로 비과세 반복 — 단 재가입 한도(연 2,000만·총 1억)에 걸려 목돈이 크면 초과분은 일반계좌 대기 | 유동성 유지(3년 사이클) + 비과세 반복 + 다음 만기에 (a) 재선택 가능한 유예. 노후 목적이면 isa1이 항상 우월(만기 특례는 만기 직후에만 적용) |
| `refund-*` (올해 세액공제 우선) | 올해 환급 현금흐름이 중요한 고객, 결정세액 충분, 특히 총급여 5,500만 이하(16.5%) | ① 연금저축 600만 → ② IRP 300만 → ③ ISA → ④ 연금저축 추가납입 → ⑤ 일반 (공제 900만 우선 소진) | 올해 확정 환급 최대 148.5만(16.5%) / 118.8만(13.2%) |
| `growth-isa3` (레거시, UI 제거) | 롤오버 안 함 — 배분이 refund와 동치라 선택지에서 제거, 저장 데이터 호환용 | refund와 동일 순서(점수에서 ISA 90→60 강등) | 중복 전략(정리 대상) |

공통 원칙: 연금저축 공제분(연 600만)은 어느 전략에서든 1순위.
직접 납입 공제(최대 16.5%)가 ISA 이전 추가공제(실효 약 1.65%)보다 10배 크고,
공제 한도는 매년 소멸(use-it-or-lose-it)하는 반면 ISA 한도는 이월되기 때문.

## B. 엔진 자동 조정 규칙 (전략 위에 상황 기반으로 적용)

| 규칙 | 발동 조건 | 조정 내용 | 근거 |
|---|---|---|---|
| 저소득 공제 무효화 | 연소득 < 1,500만(결정세액 근사) AND 나이 < 55 | 순위: ISA 1순위 승격. 금액: 연금저축·IRP 0원(공제·추가납입 차단) | 환급 없이 55세 잠김만 남는 납입 방지 |
| 55세 이상 — 중도인출 제약 소멸 | 나이 ≥ 55 | 페널티·금액 차단 전부 소멸 → 연금저축 복귀 | 연금 수령 개시가 가능한 나이라 중도인출 페널티(기타소득세 16.5%) 부담 자체가 없음 |
| 비공제 추가납입 나이 글라이드 | waterfall 4단계 도달 시 | 55세까지 잔여기간 t 기준 허용률: t≤5년 100% / t≤10년 50% / t≤15년 25% / 그외 0%. 초과분은 ISA·일반으로 | 과세이연만으로는 장기 잠김 보상이 약함 |
| 한도 소진 강등 | 계좌 올해 여력(room) = 0 | 해당 계좌 최하위(점수 −1000) — 표시 순서 = 실질 납입 순서 | 예: 연금저축 600만 기납 → ISA 실질 1순위 |
| 유동성 단기 선호 | `liquidity: "short"` (엔진 지원, 입력 UI 미연결) | ISA +30 / 연금계좌 −30(55세 미만), 추가납입 0 | 3~5년 내 목돈 계획 대응 |
| 계좌별 한도·하한 | `perAccount { monthlyMin, monthlyMax }` (프로그램 채널) | 0단계에서 하한 우선 확보, 상한 초과분은 다음 순위로. 자동 판단과 min 병합 | 전략·자동판단 위의 미세 조정 훅 |
| 수동 순위 오버라이드 | `priorityOverride: [ids]` | 점수 무시, 지정 순서(누락 계좌는 기본 순서로 뒤에) | 최후 수단 |

## D. 알려진 공백 (신규 전략·조율 후보)

- 결정세액 정밀화: 현재 소득 1,500만 근사 → 당해 소득·공제 내역 입력 필요
- 유동성 선호 입력 UI 미연결 (`liquidity` 엔진만 지원)
- ISA 한도 이월(연 2,000만·총 1억)·재가입 병목(isa2 선택 시 만기 목돈의 분할 재납입·총한도 초과분 과세 대기), ISA 서민형(총급여 5,000만 이하 비과세 400만) 미모델링
- ISA 가입 제한(금융소득종합과세 대상) 미검증 — `finIncome` 입력 자체가 수기 폼에 없음
- 소비패턴·금융선호도(productPref) 데이터 미정의
- 전략별 계좌 한도 프리셋: `perAccount` 채널은 있으나 프리셋에 값을 넣는 전략은 아직 없음
