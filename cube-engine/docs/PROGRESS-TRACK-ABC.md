## Phase 1 — 청킹 ✅

**고정 수치(테스트가 강제, Phase 3 반영 후):** 조문 2,137 → 삭제 스텁 373 제외 → **1,764 색인 대상** → **청크 2,649** (ARTICLE 1,410 / HANG 1,009 / HO 172 / CHAR 58). 문자 폴백 2.2%. 인용 엣지 579 해소 / dangling 3 (99.5%).
*(Phase 1 착수 시점의 법령 6종만 기준으로는 1,849 → 1,477 → 2,357 이었다. 행정규칙 4종이 합류하며 늘었다.)*

**설계 결정 4개**
1. **삭제 스텁 이중 술어** — `title===null` 과 정규식을 **둘 다** 검사, 어긋나면 throw. 실측 372/372 완전 일치. 한쪽만 쓰면 코퍼스 형태 변화 시 조용히 조문이 사라진다.
2. **`text` / `contextHeader` 분리** — `text` 는 원문의 정확한 슬라이스(재조립 보장), `contextHeader` 는 맥락(원문 아님). 한도 초과 항 89건 중 63건이 목을 포함해 "안 쪼갠다"는 선택지가 없었다.
3. **인접 블록 greedy 패킹** — 항 하나당 청크 하나로 만들면 **5,925 청크**(186콜). 인접 항을 묶어 **2,357**(74콜, 60% 절감) + 맥락도 두꺼워졌다. *(법령 6종 기준 측정. Phase 3 후 2,649 / 83콜.)*
4. **명시 인용만** — bare `제N조` 추정은 16% 오류라 기각(목 소속 추론 80.3% 기각과 같은 논리).

**잡은 버그 2건**
- `splitByChar` off-by-one: `lastIndexOf(" ", end)` 가 `end` 를 포함해 검색하는데 `+1` 을 해서 한도를 1 넘김.
- ★ **항이 없는 조문에서 목 맥락 소실** — `INCTAX_12`(항 마커 없음)는 호 5개 중 4개가 "각 목"을 말하는데 목이 한 덩어리로 뭉쳐 있다. CHAR 분할이 `5. 기타소득 중…` 부터 잘라놔 조각만 읽으면 **"5번 소속"으로 확정처럼 읽힌다** — 청킹이 원문의 모호함을 **거짓 확신으로 바꿈**. → 목을 담은 청크에 `MOK_CAVEAT` 필수 부착.

## Phase 2 — 임베딩 색인 ✅

실측: 최장 청크 1,793자 = **1,035 토큰**(모델 한도 안) · L2 오차 **1.5e-8**. 색인 규모는 법령 6종 기준 74콜·109초·27.6MB 였고, **Phase 3 행정규칙 합류 후 83콜·123초·31.0MB** 다.
- A1-v2 에 없던 **backoff 이식**(2·4·8s, 429 는 즉시 raise). A1-v2 는 300건이라 안 터졌을 뿐.
- **resume** — 배치마다 `.partial.bin` append + `.progress.json`. 버전이 다르면 버린다.
- 청크 텍스트를 저장하지 않는다 — `loadCorpus + chunkAll` 이 결정론적이라 재생성된다. 중복 저장하면 두 벌이 어긋날 수 있다.

## Phase 4 — 어휘 브리지 · BM25 · 시점 필터 ✅

- **글자 2-gram** — A1 이 공백 split + FTS5 로 `"강나영은"` ≠ `"강나영"` 이 되어 BM25 절반을 잃은 실패를 구조적으로 회피. 조사 10종 전부 테스트.
- **`vocab/aliases.json`** — ★ 전 항목 `approved:false`(사람 승인 대기). 미승인은 확장에 안 쓰이고 건너뛴 사실이 보고된다.
- **시점 필터** — ⚠️ 실코퍼스에서 **0건을 거른다**(미래 시행 조문 0, validFrom 값 3개). fixture 로만 검증 가능하며 그 vacuity 를 테스트가 명시한다.

**별칭 효과 실측 (정직한 축소)**
| 조건 | 효과 |
|---|---|
| BM25 단독 · 약어 단독(`"ISA"`) | 0건 → rank 1. 결정적 |
| BM25 단독 · 약어+맥락 | rank 3 → 1. 개선 |
| **하이브리드** | 대부분 **차이 없음** — 벡터가 이미 의미를 잡는다 |

→ 별칭은 **BM25 절반을 살리는 장치**이지 하이브리드 전체의 필수 부품이 아니다. 표본 5개로 결론짓지 않고 Phase 6 이 버킷별로 다시 쟀다.

## Phase 5 — 하이브리드 + CLI ✅ ★첫 데모

`npm run ask -w @cube/factindex -- "질문"`

★ **하이브리드가 BM25 단독의 오답을 고쳤다**: `"IRP 중도인출 사유"` 를 BM25 만으로 돌리면 **RETIRE_D_14(확정기여형=DC)** 가 1위인데, 벡터를 넣으면 **RETIRE_D_18(IRP)** 로 뒤집힌다. 세션 초반에 사람이 저지를 뻔한 오인용과 같은 실수 — 어휘 매칭은 `확정기여형` 과 `개인형` 을 못 가른다.

**조문 단위 접기** — 같은 조문의 청크를 최고점 하나로 접는다. 안 접으면 긴 조문이 top-5 를 독차지한다(실제로 같은 조문이 3번 나왔다).

## Phase 6 — 평가셋 + 게이트 ✅

4버킷 30문항(exact 8 / semantic 8 / josa 8 / out 6). 정답은 조문을 읽고 **손으로 썼다**. ★ `reviewer: null` — 사람 서명 전이므로 이 수치는 "측정했다"이지 "검증됐다"가 아니다.

**잡은 결함 2건**
1. ★ **exact 버킷이 38%였다** — `"소득세법 시행령 제118조의3"` 에 `INCTAX_D_178_4` 가 1위. 조문번호가 2-gram 으로 흩어져 숫자가 비슷한 조문과 섞인다. **검색이 아니라 파싱 문제** → `exactRef.ts` 로 "법령명 + 제N조(의M)" 를 파싱해 1위 고정. **38% → 100%.**
2. **out 버킷 1위 점수가 0.890** — min-max 가 후보 집합 내부 정규화라 **1위는 항상 1.0 근처**다. A1 의 "score gate 가 13건 중 0건 발화 = dead" 와 같은 구조. → 정규화 전 `rawVector`(절대 코사인)를 결과에 실었다. **거부 판정은 융합 점수로 못 한다** — Phase 9 가 Registry 유무로 판정해야 한다는 계획의 근거가 측정으로 확인됐다.

**복수 정답 허용** — 법률(`RETIRE_22`)과 시행령(`RETIRE_D_14`)이 같은 사안을 나눠 규정하면 **둘 다 정당한 근거**다(사양 §5.1 PRIMARY / IMPLEMENTING_DETAIL). 시행령만 정답으로 둔 것이 애초에 실수였다. *근거는 사양이지 측정 결과가 아니다 — "결과에 맞춰 평가셋을 고친 것"이 아님을 각 항목 `why` 에 적었다.*

## Phase 8 — policy 구멍 메우기 ✅

세 구멍 전부 **에러를 내지 않는** 종류였다.

- **8-1 `role` 노출** — `registry.ts` 가 `sources.map(s => s.source_id)` 로 role 을 버려서 "PRIMARY 만 인용" 이 불가능했다. `RuleMetadata.sources`(id+role)를 **추가**(기존 `sourceIds` 는 호환 유지). 행정해석이 PRIMARY 로 둔갑하면 근거 등급이 조용히 올라간다. role 은 effect 값이 아니라 스탬프 없이 나가도 안전하다.
- **8-2 FACT 매니페스트 스탬프 자리** — `FactAnswerManifest` 에 `packKind`/`syntheticStamp` **추가**(사양 §5.6 확장, 개명·삭제 없음). 봉투에만 스탬프를 실으면 **보관된 매니페스트만 봐선 합성 값 여부를 알 수 없다** — 사양 §1.3 이 재현성 단위를 매니페스트로 정의했으므로 매니페스트도 출력이다. `RunManifest` 의 `SYNTHETIC_STAMP_REQUIRED` 분기를 복제(기존 code 라 union 추가 불필요).
- **8-3 이음매 검사** — `loadPolicyPack(raw, { knownSourceIds })`. 계층 역전(policy→corpus)을 피하려 **주입** 방식. 미지정 시 미검사(기존 호출 무회귀), `SYNTHETIC_DEMO` 는 면제(합성 팩이 합성 출처를 갖는 건 정상). 새 code `SOURCE_SNAPSHOT_NOT_FOUND` = 매트릭스 **R67**.

**잡힌 것 2건**: ① `matrix-coverage.test.ts` 가 **새 code 를 매트릭스에 안 적은 것을 잡았다** — 레포 규약이 실제로 작동한다는 증거. ② 내 테스트가 `source_id` 를 바꿔 `DANGLING_FIELD_BINDING` 을 먼저 유발 → 기존 것을 바꾸지 않고 **추가**하도록 수정.

행정규칙 4종 **288개 조문** 수집: `PENSUP` 퇴직연금감독규정(금융위 고시, RULE) 34 · `PENSUPD` 시행세칙(금감원 세칙, RULE) 9 · `NTSWHT` 원천징수사무처리규정(국세청 훈령, ADMIN_GUIDANCE) 79 · `NTSINC` 소득세사무처리규정(국세청 훈령, ADMIN_GUIDANCE) 166.

### ★ "API 범위 밖" 이라던 판단이 틀렸다

처음엔 "국세청 자료는 법제처 API 밖이라 스크래핑이 필요하고, 그래서 사람 게이트 2건에 막혔다"고 적었다. **확인하지 않고 내린 판단이었다.** 두 경로를 실제로 재보니:

- `target=expc`(법령해석례) — 법제처 해석례라 우리 도메인엔 거의 없다(`연금계좌` 0건, `개인종합자산관리계좌` 0건). **확인하고 없음**으로 확정.
- `target=admrul` — **국세청 훈령이 여기 있었다.** 원천징수사무처리규정 · 소득세사무처리규정.

→ **스크래핑 게이트가 사라졌다.** 이미 승인된 같은 API다. 남은 것은 예규·질의회신뿐이고 그건 `txsi.hometax.go.kr` 별도 시스템이라 진짜 API 밖이다.

### 서열 판단을 heuristic 에서 사람 선언으로

`mapAdmRulAuthority(kind)` 가 종류만으로 등급을 반환하던 것을 **거절**로 바꿨다. 같은 "고시"라도 등급이 다르다 — 법령 위임을 받은 법규명령성 고시(금융위)는 `RULE`, 내부 사무처리 훈령(국세청)은 `ADMIN_GUIDANCE`. 수집 타깃에 사람이 명시한다. ⚠️ 현재 판단은 **잠정**(BUILD-PLAN Q7).

### 코퍼스 확장이 드러낸 결함 2건

**① 삭제 스텁 이중 술어의 전제가 법령 특유였다.** `title===null` ⟺ 정규식 동치가 법령 372/372 에서 성립했는데, 행정규칙이 합류하자 깨졌다 — **행정규칙은 삭제해도 제목을 남긴다**(`제5조의3(표준투자권유준칙) 삭제`). 삭제의 진짜 신호는 "제목 없음"이 아니라 "본문이 삭제 표기뿐"이었다. **이중 술어 가드가 그 사실을 실패로 드러냈다.** → 정규식을 두 형태 모두 받게 확장하고 제목 교차검증은 법령 계층에만 건다.

**② ★ 사양 §5.1 권위 서열이 검색 순위에 반영되지 않고 있었다.** `"ISA"` 질의에서 `NTSWHT_59`(국세청 훈령 = ADMIN_GUIDANCE)가 `TAXEX_91_18`(조세특례제한법 = **STATUTE**)을 밀어냈다. BM25 관점엔 정당하지만 **법률이 행정안내에 밀리면 인용 등급이 뒤집힌다.** 계층이 하나뿐일 땐 안 보이던 결함. → `foldToArticles` 에 **점수 차 5% 이내면 서열이 가르는** tie-break 추가(차이가 크면 점수가 이긴다).

### 회귀를 게이트가 잡았다

Phase 3-b 후 hit@1 이 22→21 로 떨어져 게이트가 실패했다. 원인은 **시행세칙(`PENSUPD_5_2`)이 고시(`PENSUP_12`)를 밀어낸 것**. 고시와 세칙은 같은 위임 사슬 안이라 법률↔시행령 쌍과 동일한 구조이므로 복수 정답에 포함했다 — **근거는 사양 §5.1 이지 측정 결과가 아니다.**

## Phase 7 — LLM rerank + ablation ✅

배치 1콜 채점 + graceful degrade. **LLM 이 무엇을 뱉든 던지지 않는다** — 실패하면 hybrid `fused` 순서를 그대로 준다. 부분 채점도 흡수(채점 안 된 후보는 fused 로 메움, 둘 다 0~1 스케일이라 순위가 안 깨진다).

**★ ablation (`npm run ablate:rerank`) — A1/A1-v2 가 한 번도 재지 않은 수치**

```
exact     n= 8  off 8/8  → on 8/8   ( 0)   ← 조문 직접 지정은 pinned 라 재정렬 제외
semantic  n=10  off 8/10 → on 10/10 (+2)
josa      n= 8  off 6/8  → on 6/8   ( 0)
전체      n=26  off 22/26 → on 24/26 (+2)
```

순위가 바뀐 5건 중 **고침 3 · 이동 1 · ★망침 1**:
- 고침: `"연금 받을 때 떼는 세금 비율"` 2→1 · `"IRP 부담금 한도"` 2→1 · `"원천징수세율은 얼마인가요"` 2→1
- 이동: `"ISA 만기 때 연금계좌로 옮기면"` 8→5 (미해결 결함 1이 개선됐으나 여전히 오답)
- **★망침: `"연금계좌세액공제를 받으려면"` 1→4** — 원래 1위였던 `INCTAX_59_3` 을 밀어냈다

**정직한 판정:** 순증 +2 이지만 **1건을 망쳤다.** 개선 총량만 보고하면 이 손실이 숨는다. 스크립트가 `★망침` 을 별도로 세어 경고하는 이유다. 표본 26건에서 순증 2건은 통계적으로 강한 근거가 아니므로, **"rerank 를 켠다"는 결정은 평가셋이 사람 서명을 받은 뒤로 미룬다.**

⚠️ rerank 점수는 **순위에만** 쓴다. 거부 판정에 쓰면 A1 의 dead score gate 를 재현한다.

## Phase 9 — 인용 기반 답변 ✅ (2026-07-31)

`npm run answer -w @cube/fact -- "ISA 비과세 한도 얼마야?"` — **미션 1 이 처음으로 "답"을 낸다.**

### ★ 설계 정정 — 사양을 과하게 좁게 읽었다

이전 계획은 "승인된 규칙이 없으면 원문만 던지고 끝"이었다. 다시 읽으니 §7 이 금지하는 것은
"AI 가 값을 **결정**한다"(= 공식 팩트로 확정하는 권한, §1.1 상 Registry 의 것)이고,
§1.2 UNMODELED 행은 **"개인 상황 적용 금지 · PLAN 엔진 입력 금지"** 라고만 한다 —
**숫자 언급을 금지하지 않는다.**

| | 예시 | 판정 |
|---|---|---|
| 인용·종합 | "조문에 따르면 400/200만원, 조건은 …[원문]" | ✅ |
| 개인 적용 | "**당신은** 400만원입니다" | ❌ §1.2 |
| 계산 투입 | 400만원을 Tax Calculator 입력으로 | ❌ 절대 규칙 1·3 |

→ **미션 1 답변은 LLM 이 조문을 읽고 정리해도 된다. 승인은 미션 2 계산값에만 필요하다.**

그리고 오늘의 400↔200 사고는 **LLM 이 못 읽어서가 아니라 파싱이 원문을 망가뜨려서**였다.
교훈은 "LLM 에게 읽히지 마라"가 아니라 **"원문을 온전하게 줘라"** 였다.

### 실제 출력 (승인 규칙 0건 상태)

```
Q. ISA 비과세 한도 얼마야?
[원문 인용 · 검증된 규칙 아님]

비과세 한도금액은 가입일 또는 연장일 기준 다음 구분에 따른다 [1].
1. 400만원 [1] — 다음 각 목 중 하나 [1]
   · 직전 과세기간 총급여액 5천만원 이하인 거주자 … [1]
   · 종합소득금액 3천8백만원 이하인 거주자 … [1]
   · 대통령령으로 정하는 농어민 … [1]
2. 200만원 [1] — 위에 해당하지 않는 경우 [1]
초과분은 「소득세법」 제129조에도 불구하고 100분의 9 세율, 종합과세 미합산 [1].

[1] 조세특례제한법 제91조의18 · 시행 2026-01-01 · STATUTE · 해시 61495aaf…
    ⚠️ 소속 호 미상인 「[각 목]」 항목 포함

검증: 위조 인용 0 · 인용 없는 주장 0 · 조건 앵커 재현율 100% · 금지 문구 없음 → 내보내기 가능 ✓
```

**400/200 이 조건과 올바르게 짝지어졌다** — 세션 초반에 뒤집혔던 바로 그 지점이다.

### 만든 것 4개

- **`bundle.ts` 조문 묶음** — 검색 씨앗 + **나가는 인용**(참조하는 조문) + **들어오는 인용**(위임 사슬 아래쪽).
  인용 엣지 579 중 544 가 법령 간이라 **인용 폐포가 곧 위임 사슬**이었다(별도 메커니즘 불필요).
  1홉만 연다 — 2홉이면 소득세법 전체가 딸려온다. 씨앗은 상한에 걸려도 절대 안 잘린다.
- **`answer.ts` 인용 강제** — 조문을 **전문 그대로** 주고 문장마다 `[n]` 을 달게 한다. 요약하면 조건이 날아간다.
- **`verifyCite.ts` 인용 검증** — `[n]` 이 제공 조문 밖이면 **위조**로 잡는다. Perplexity 의 알려진 결함
  (없는 출처 지어내기)을 우리는 **컨텍스트가 닫힌 집합이라 기계적으로 막을 수 있다.**
- **`coverage.ts` 조건 누락** — 숫자 오류보다 위험하다. "400만원"이 맞아도 농어민 조건을 빼먹으면
  해당자가 자기가 대상인지 모른다. 틀린 게 아니라 **불완전한데, 불완전은 조용하다.**

### 조건 검사를 두 번 고쳤다 — 오탐 제거

| 단계 | 재현율 | 문제 |
|---|---|---|
| 조문 전체 앵커와 비교 | 38% | ①항 가입요건(`19세`·`3년`·`1억원`)이 한도 질문에 누락으로 잡힘 |
| **항 단위로 범위 축소** | 60% | 답변이 ①항의 `100분의 9` 만 언급했는데 그 항 전체를 요구 |
| **앵커 2개 이상 일치해야 "다뤘다"** | **100%** | 1개는 우연일 수 있다 |
| + 마크다운 bullet 도 열거로 카운트 | 100%, 경고 0 | LLM 은 호를 번호로, 목을 bullet 으로 쓴다 |

**경고가 사라질 때까지 조이지 않았다** — 유닛 테스트(의도적 조건 누락)가 계속 통과하는지 매번 확인했다.
그리고 `isPublishable` 은 조건 커버리지를 **차단하지 않는다**. 위조 인용·금지 문구만 막고,
커버리지는 사람이 볼 신호로 남긴다. 항상 켜지는 경고는 아무도 안 본다.

### 드러난 한계

**같은 법령 안의 bare 참조는 묶음에 안 들어온다.** `"IRP 중도인출 사유"` 답변에서:
```
1. 제2조제1항제1호에 해당하는 경우 [2]. (다만, 해당 조문의 구체적인 내용은 제공된 조문에서 확인되지 않는다.)
```
`RETIRE_D_18` 이 같은 법령의 `제2조` 를 bare 로 참조하는데 인용 그래프가 명시 인용만 잡아
`RETIRE_D_2` 가 빠졌다. **LLM 이 지어내지 않고 "확인되지 않는다"고 말한 것은 grounding 이 작동한 증거다.**

→ 개선 후보: **같은 법령 안의 bare 참조는 확장해도 안전할 수 있다.** Phase 1 에서 bare 확장을
16% 오류로 기각했는데, 그 실패는 전부 **법을 잘못 붙인 경우**(`INCTAX_91_18` 등 존재하지 않는 id)였다.
**코퍼스 실재 여부로 필터하면** 그 부류는 자동으로 걸러진다. 다만 "존재하지만 다른 법을 가리키는" 경우가
남으므로 **측정 후 결정**해야 한다(Phase 1 의 `measure-mok.ts` 와 같은 방식).

### bare 참조 확장 — 측정하고 채택했다 ✅

한계를 발견하고 **추측 대신 측정**했다(`npm run measure:bareref -w @cube/factindex`):

```
bare 참조 5,790  (자기참조 1,764 제외 → 4,026)
  코퍼스 실재  3,238 (80.4%)
  dangling      788 (19.6%)  ← 실재 필터가 자동으로 거른다
```

**dangling 의 정체가 예상과 달랐다.** 샘플이 `INCTAX_17→INCTAX_13`, `INCTAX_78→INCTAX_49` 처럼
**같은 법 안의 정당한 참조인데 대상이 「삭제」 스텁**이라 색인에서 빠진 경우였다.
"법을 잘못 붙인" 것이 아니었다.

**★ 그런데 채택 근거는 정확도가 아니라 "용도가 다르면 기준도 다르다" 였다.**

| | 인용 그래프 (Phase 1, 기각) | 묶음 확장 (Phase 9, 채택) |
|---|---|---|
| 무엇인가 | "이 조문이 저 조문을 인용한다"는 **사실 주장** | 조문을 **후보로 넣는 것** |
| 틀리면 | 근거가 거짓이 된다 | 질문과 무관해 LLM 이 인용 안 함 → unused ref 로 버려짐 |
| 비용 | 정확도 | **프롬프트 토큰** |

`buildUnmodeledAnswer` 가 **인용된 조문만** 근거로 싣기 때문에 출력 단계에서 한 번 더 걸러진다.
같은 16% 라도 쓰이는 자리가 달라 기준이 달라진 것이다.

**효과 (실측, `"IRP 중도인출 사유가 뭐야?"`)**

`RETIRE_D_2`(담보제공 사유)가 `[6]` 으로 합류해 **"확인되지 않는다" 4건이 실제 사유로 채워졌다.**

*LLM 이 없는 내용을 지어내지 않고 "확인되지 않는다"고 말했던 것 자체가 grounding 이 작동한 증거였고,
그 신호를 보고 묶음을 고친 것이다 — 답을 고친 게 아니라 **재료를 고쳤다.***
