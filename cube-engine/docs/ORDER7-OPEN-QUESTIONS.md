## 라우터가 지키는 것 (딱 하나)

사양 §1.2 는 `UNMODELED_OFFICIAL_SOURCE` 에 대해 **개인 적용 금지**를 못 박는다.
그런데 "나 연봉 6천인데 IRP 얼마 넣어야 돼?" 를 그대로 FACT 엔진에 넣으면, LLM 은 조문을 읽고
**개인에게 맞춘 답을 쓰려고 한다.** 프롬프트로 막는 건 사후 방어고, 그 질문이 엔진에
도달하지 않게 하는 것이 사전 방어다.

그래서 라우터의 역할은 "질문 분류"가 아니라 **"PLAN 질의를 FACT 엔진에서 떼어내는 것"** 하나다.
도메인 밖 질문(예: 날씨)은 라우터가 아니라 **검색 0건 → 거절**이 처리한다 — 주제 분류기를 따로
만들지 않은 이유는, 코퍼스가 이미 그 판단을 내려주기 때문이다(사다리 2단: 이미 있는 걸 쓴다).

## 왜 LLM 을 안 쓰나

- **재현성(§1.3):** 같은 질문은 항상 같은 분기로 가야 한다. LLM 분류기는 그 보장이 없다.
- **비용:** 라우팅에 콜을 쓰면 질문당 API 콜이 2 → 3 이 된다. 걷어낼 질문에 돈을 쓰는 셈.
- **손해의 비대칭:** 틀려도 방향에 따라 손해가 다르다.
  - PLAN → FACT 로 잘못 흘리면 **§1.2 가 뚫린다** (개인 맞춤 답이 나간다).
  - FACT → PLAN 으로 잘못 보내면 "미션 2 미구현" 안내가 나가고 사용자가 다시 물으면 된다.
  - 그래서 **PLAN 쪽으로 기울여** 설계했다.

## 판별 기준 (현재)

| 종류 | 예시 | 단독으로 PLAN? |
|---|---|---|
| **개인 지시어** | `나는`, `내가`, `제가`, `저는`, `내 소득`, `저희` | ✅ |
| **개인 소득 진술** | `연봉 6000`, `월급 300`, `소득이 5000` | ✅ |
| **개인 상황 어미** | `35살인데`, `40세인데`, `50살이고` | ✅ |
| **조언·설계 요구** | `추천`, `유리한`, `최적`, `얼마 넣`, `짜줘`, `절세하려면` | ✅ |
| **나이 수치(약)** | `40세`, `35살` | ❌ — 다른 신호와 2개 이상 겹칠 때만 |

### 왜 나이만 약한 신호인가 (실측)

`40세 이상 가입 제한이 있나` 는 **조문의 가입 요건**을 묻는 FACT 질의인데,
`\d+세` 패턴만 보면 `저 40세인데` 와 구별이 안 된다. 실제로 이 케이스가 PLAN 으로 잘못 갔다.
반면 **연봉·월급 액수는 조문이 쓰지 않는 표현**이라 강한 신호로 두어도 안전하다.
나이는 "어미가 붙은 상황 진술"(`40세인데`)일 때만 강한 신호로 승격했다.

### 한국어 부분문자열 함정

`내`·`제`·`저` 를 그냥 `includes` 하면 아래가 전부 걸린다 (실측):

| 걸리는 것 | 원인 |
|---|---|
| `소득세법 제55조` | `제` |
| `국내외 소득` | `내` |
| `저축성보험 과세` | `저` |
| `내국법인 원천징수` | `내` |

그래서 개인 신호는 **조사까지 붙은 2글자 이상 토큰**으로만 잡는다 (`내가`, `제가`, `저는`).
회귀 테스트로 고정돼 있다.

## 열린 질문 (사람 확인 필요)

### Q7-1. 어휘 목록 밖 표현은 어떻게 잡을 것인가 🔴
현재는 규칙 기반이라 목록에 없는 표현("이 상황에서 뭘 골라야 하나요")은 FACT 로 샌다.
- **지금의 방어선:** 답변 프롬프트(§4.4 금지 문구) + `resolve.ts` 의 출력 검사.
  즉 라우터가 새도 **두 번째 그물**이 있다.
- **업그레이드 경로:** 오분류 사례를 이 문서에 모아 목록을 늘린다.
  분류기를 학습시키는 방향은 재현성(§1.3)을 깨므로 택하지 않는다.
- **필요:** 실제 사용자 질문 20~30건 수집 후 재검토.

### Q7-2. `얼마` 계열 어휘를 어디까지 PLAN 으로 볼 것인가 🟡
- `얼마 넣어야` → PLAN (설계 요구) ✅ 확정
- `한도가 얼마인가` → FACT (조문 조회) ✅ 확정
- `얼마까지 넣을 수 있나` → **미확정.** 조문 조회로도, 개인 설계로도 읽힌다.
  현재는 `얼마 넣` 에 걸려 **PLAN 으로 간다**(안전 쪽). 과장님 확인 필요.

### Q7-3. PLAN 안내문에 "이렇게 물어보세요" 예시를 몇 개 둘 것인가 🟢
현재 2개. 예시가 많으면 사용자가 FACT 로 유도되지만, 안내문이 길어지면 안 읽는다.
발표 피드백 후 조정.

### Q7-4. 라우터 통계를 남길 것인가 🟢
어떤 신호에 몇 건이 걸렸는지 로그가 있어야 Q7-1 을 데이터로 풀 수 있다.
현재 `RouteResult.matched` 로 응답에는 실리지만 **집계는 하지 않는다.** 미션 1 범위 밖.

## 확정된 것

- ✅ 라우터는 **결정론적 규칙**이다. LLM 을 쓰지 않는다.
- ✅ PLAN 판정 시 **계산을 하지 않고 안내만** 한다 (`renderPlan`, 숫자 없음 — 테스트로 고정).
- ✅ PLAN 질의는 **검색·LLM 을 아예 타지 않는다** (API 콜 0회). 실측으로 확인.
- ✅ 도메인 밖 질문은 라우터가 아니라 검색 0건 → §4.2 거절이 처리한다.
