## 4. 구조적 한계 (고칠 수 없어서 표시만 한 것)

### 4.1 `[각 목]` 소속 호 미상 — **293 조문**

법제처 API 가 `목`을 `호`의 자식이 아니라 **`항`의 형제**로 내려주고 부모 호 참조가 없다.

- "다음 각 목" heuristic 을 **238개 항 실측 → 80.3% 일치** 로 측정하고 **기각**했다.
- 이 도메인에서 20% 오류는 "5건 중 1건을 **조용히** 틀리게 붙임"이고, 실제 사례가 하필 **ISA 비과세 한도 400/200만원 뒤집힘**이었다.
- 대신 소속 미상 목에 **`[각 목]` 표식**을 달아 텍스트에 드러낸다. 답변에도 caveat 이 붙는다.
- **업그레이드 경로:** 조항호목 단위 API(`lsNwJoListGuide` 계열)가 부모 참조를 주는지 확인 → 주면 교체하고 표식 제거.
- 재현: `npm run measure:mok -w @cube/corpus` (API 0콜)

### 4.2 시점 필터는 실코퍼스에서 **0건을 거른다**

미래 시행 조문이 코퍼스에 없어서 필터가 실제로 발화한 적이 없다. **fixture 로만 검증됐고, 그 vacuity 를 테스트가 명시한다.**

다만 `validFrom` 이 못 잡는 것을 따로 잡는다 — **조문은 살아 있는데 그 안의 규정이 이미 끝난** 경우(`TAXEX_86_4` 는 시행 2026-01-01 인데 내용은 "2022년 12월 31일까지"의 한시 규정). 본문의 적용기한을 스캔해 답변에 경고를 붙인다.
재현: `npm run scan:deadlines -w @cube/corpus` (API 0콜)

### 4.3 인용 확장은 **명시 인용 한정**

- 인용 **그래프**(사실 주장): 명시 인용만. bare `제N조` 추정은 **16% 오류**로 기각.
- 인용 **묶음**(후보 넣기): bare 참조를 **코퍼스 실재 필터**로 걸러 확장 — 채택.
- **같은 16% 인데 판정이 갈린 이유:** 그래프는 "이 조문이 저 조문을 인용한다"는 사실 주장이라 틀리면 근거가 거짓이 되고, 묶음은 후보라 틀려도 LLM 이 인용 안 해 버려진다. **용도가 다르면 기준도 다르다.**
- 재현: `npm run measure:bareref -w @cube/factindex` (API 0콜)

### 4.4 조건 앵커 채점기 — 큰 호에서 오탐이 남는다

`hit >= 2` 게이트로 "답변이 다룬 호"만 검사하는데, 소득세법 제129조처럼 **한 호에 세율이 17개**인 조문은 연금 세율만 언급해도 게이트를 통과하고 이자·배당용 세율까지 누락으로 잡힌다.

- **과반 게이트(`hit > missing`)를 시도했다가 되돌렸다.** 나이는 맞고 세율은 셋 다 틀린 답에 만점을 주기 때문이다 — "큰 호를 스쳤다"와 "다뤘는데 숫자를 틀렸다"를 구분 못 한다. 전 리포트 평균이 84~98% 로 뛰었고, 그건 **지표가 측정을 멈췄다**는 뜻이다.
- 코드에 `KNOWN-LIMITATION(coverage)` 마커 + 재현법(`5% ≠ 15%` 회귀 테스트) 을 남겼다.
- **정식 해결은 조건을 구조화한 정책 팩** — 그때는 조건이 데이터라 기계적으로 확인된다.

## 5. 튜닝되지 않은 것 (기본값을 쓰고 있음)

### 5.1 융합 가중치 0.5 / 0.5 — **스윕이지 최적화가 아니다**

BM25 와 벡터의 융합 비율은 **한 번도 스윕된 적 없는 시작값**이다. `--sweep` 로 3점 스윕(0.3/0.7 · 0.5/0.5 · 0.7/0.3)이 가능하나 실행하지 않았다. **"0.5/0.5 가 최적"이라고 말하면 안 된다.**

### 5.2 rerank 채택 **보류**

LLM rerank ablation 결과:
```
exact     n= 8  off 8/8  → on 8/8   ( 0)
semantic  n=10  off 8/10 → on 10/10 (+2)
josa      n= 8  off 6/8  → on 6/8   ( 0)
전체      n=26  off 22/26 → on 24/26 (+2)
```
순증 +2 이지만 **`"연금계좌세액공제를 받으려면"` 1위 → 4위로 1건을 망쳤다.** 표본 26건에서 순증 2는 통계적으로 강한 근거가 아니다. → **평가셋이 사람 서명을 받은 뒤 재측정 후 결정.** 현재 게이트 수치는 rerank **끈 상태**다.

### 5.3 답변 모델 설정 — `effort=medium` (2026-08-07 결정)

7칸 스윕 후 채택. 넓은 질문 **30.9초 → 22.2초 (28% 단축)**, 품질 손실 0(인용률·위조 동일, 앵커 87% vs 85% = 노이즈 범위).
- `effort=low` 는 4.5초를 더 벌지만 **가장 복잡한 문항의 앵커가 100% → 40%** 로 떨어져 폐기.
- 생각(thinking) 억제·차단 4칸은 **전부 baseline 보다 느렸다.** 병목은 thinking 이 아니라 답변 텍스트 길이였다.
- 매니페스트에 `claude/claude-sonnet-5[effort=medium]` 으로 기록된다(§1.3 재현성).

## 6. ★ 검증 상태 — "측정했다"와 "검증됐다"는 다르다

### 6.1 사람 확인이 **아직 0건**이다

`docs/ANSWER-QUALITY-*.md` 20편 이상에 문항마다 `사람 검증:` 칸이 있다:
```
- [ ] 사실이 맞다
- [ ] 조건이 빠지지 않았다
- [ ] 오해를 낳지 않는다
```
**전부 비어 있다.** 기계가 잰 것은 위조 인용·조건 앵커·금지 문구 같은 **형식**이고, *그 문장이 사실인가*는 사람이 원문과 대조해야 한다.

### 6.2 정답지 서명 현황

| 평가셋 | 문항 | authority |
|---|---:|---|
| `queries.json` | 31 | **ORACLE** |
| `user-queries.json` | 21 | DRAFT |
| `narrow-queries.json` | 10 | NOT_AN_ORACLE |
| `wide-queries.json` | 8 | NOT_AN_ORACLE |
| `scope-queries.json` | 8 | NOT_AN_ORACLE |

`NOT_AN_ORACLE` 은 **회귀 감지용 생성 파일**이지 정답지가 아니다. 이 세트의 수치로 "정확도"를 주장하면 안 된다.

### 6.3 기계 교차검증에서 **✗ 5건**

검사자 `gemini-2.5-flash` / 작성자 `claude-sonnet-5` — **서로 다른 provider**(사양 §2.2 독립성). 21문항 중 ○16 · ✗5.

**사람이 먼저 볼 5건** (`docs/CROSSCHECK-USER.md`):
1. 연금계좌 납입한도와 세액공제 한도가 같은 금액인가
2. 개인형퇴직연금을 중간에 인출할 수 있는 사유가 뭔가
3. 연금계좌에 있는 돈을 다른 연금계좌로 옮길 수 있나
4. 세액공제를 못 받은 납입금을 다음 해로 넘길 수 있나
5. 퇴직연금 적립금의 위험자산 투자 비중에 한도가 있나

> ⚠️ 이것도 **사람 검증이 아니다.** 기계가 원문과 답을 대조한 결과이고, 쓰임새는 "어디를 먼저 볼지 좁히는 것"이다. `○` 라도 검사자가 놓쳤을 수 있다.

### 6.4 아직 안 들여다본 지표

**무인용 주장**이 문항당 0~5건 잡히는데, 진짜 근거 없는 단정인지 검사기가 인용 표기를 못 읽은 오탐인지 **확인하지 않았다.** 조건 앵커에서 겪은 것(채점기 자체가 틀렸음)을 생각하면 후자일 가능성도 있다.
